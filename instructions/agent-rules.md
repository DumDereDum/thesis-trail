# ThesisTrail agent instructions

Follow the student's requested scope and communicate in their language. Installation alone does not authorize editing student documents, committing, or publishing changes. Do not start student onboarding merely because someone is maintaining ThesisTrail itself.

## At the start of a session

- Read the [release instructions](maintenance/updates.md) and follow the interval-limited check and explicit update consent. Do not repeat the check on every message.
- If `.tt/setup-state` exists, read the [initial setup instructions](maintenance/project-setup.md) before topic onboarding. Pending setup takes priority within the student's requested scope; completed setup does not restart.
- For substantive coursework or thesis work, read the [topic instructions](research/topic.md) and the existing project topic card. Reuse known context and accepted decisions.
- If a material library or catalog exists and setup is not pending, follow the read-only session check in the [material instructions](research/materials.md).

## Choose instructions for the task

| Instructions | When to read and apply |
| --- | --- |
| [Git](general/git.md) | Working with branches, commits, history, or publication. |
| [Reproducibility](general/reproducibility.md) | Setup, dependencies, configuration, data, experiments, results, or minimal CI. |
| [Documentation](general/documentation.md) | Creating or changing a README or other project documentation. |
| [Topic and research decisions](research/topic.md) | Forming a topic, using its context, or reconsidering a consequential research choice. |
| [Reference materials](research/materials.md) | Organizing, finding, reading, or citing sources, or checking an existing library. |
| [Domains](domains/README.md) | Giving an early overview of relevant recommendations when planning the work; applying selected areas during concrete tasks. |

Read the relevant modules before acting and reuse them during the conversation. Do not load the entire collection or restart research framing for every small task. Domain instructions supplement the general and research instructions; use only modules that exist and actually apply. Clarify substantive conflicts instead of silently replacing an accepted decision or project requirement.

Student files, topic cards, catalogs, and originals belong to the project. Keep custom instructions outside managed ThesisTrail files. See the [release instructions](maintenance/updates.md#file-ownership) for ownership and update behavior.
